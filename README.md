# 政务数据集质量评估 Demo

版本：v1.1

一个本地运行的 Streamlit Demo，用于对 CSV、Excel（`.xls`、`.xlsx`）、表格型 JSON、JSON Lines、GeoJSON FeatureCollection 和同构 JSON 分片 ZIP 数据集生成可复现的质量指标、风险提示、疑似问题位置 CSV 与无法评估项。

v0.6 **直接以 v0.4 为基础开发，不包含或继承 v0.5 的跨历史版本比较能力**。它完整保留 v0.4 的 13 项原有指标，并加入 DB31/T 1523-2024《公共数据质量评价要求》正文中的 30 项指标，形成 43 项可选目录。v0.7 在此基础上增加补充评价标准 Agent；v0.8 新增自然语言自定义规则入口，支持格式/正则、字符长度、条件必填和跨字段比较；v0.9 增加本地、可审计的标准依据 RAG；v0.9.1 新增可重放 Agent Harness、版本化提示词、严格模型输出边界与隐私受限的运行轨迹；v1.0 将规则编制闭环收口为显式、可恢复、可追溯的确定性工作流；v1.1 将规则生成前移到最终评估之前，并增加默认指标补充规则、自然语言规则输入和规则文件批量导入。规则仍经确定性校验、试运行和人工批准后执行，既有指标、风险和报告口径保持不变。

DB31/T 指标采用严格评价口径：当前单表上传数据可以直接支撑 `030300 数据重复率` 和 `030400 数据唯一性`；其余 28 项需要数据标准、业务规则、权威参照、多表关系、授权信息、访问 SLA 或应用场景等额外依据。缺少这些依据时，报告会明确标记“无法评估”并列出所需输入，不会把原有启发式指标当成标准符合性结论，也不会用 0 代替。

完整代码、公式和 v0.6 能力映射见 [DB31T_1523-2024_指标与v0.6实现口径.md](./DB31T_1523-2024_指标与v0.6实现口径.md)。

v0.4 已有的只读报告诊断 Agent 和待审批 `RulePack` 规则增强闭环继续保留：用户可引导式确认主键、必填、更新时间与更新频率、允许值和数值范围，经本地确定性校验和明确批准后生成独立的规则增强报告。

v0.7 新增“补充评价标准”页签；v0.8 在同一审批链中新增“自定义规则”入口；v0.9 新增“标准依据 RAG”页签。RAG 首版支持项目预置及用户明确批准的 Markdown、TXT 和可抽取文本层 PDF，按标题、条款、段落和表格行切分，使用本地确定性关键词/中文 n-gram 混合检索，并在绑定时保存文档名称、标准号、版本、章节/条款、页码/行号和稳定 chunk ID。未命中来源、命中版本冲突或来源命名空间冲突时不能直接生成标准依据。自定义规则支持格式/正则、字符长度、条件必填和跨字段比较，范围外的跨表参照、任意 Python/SQL、自动清洗和数据写回会明确拒绝。模型只负责理解和编译；字段/参数校验、引用校验、审批前试运行、审批和正式重评均由本地 Python 确定性代码完成。初始页面可填写 API 地址、API Key 和模型名称，调用兼容 OpenAI Chat Completions 格式的自定义模型；已配置外部模型时调用或解析失败会直接提示错误，绝不伪装成模板结果。未配置 API Key 时才使用本地模板作暂行演示。LangGraph 和 Dify 仍未接入。

v0.9.1 Harness 固化了 29 个规则编译金标案例和 6 个 RAG 检索/引用案例；9 种白名单规则分别覆盖正常、边界和错误/澄清路径，并补充范围外拒绝、无结果、版本冲突、未批准/过期来源和错误版本。规则案例重放时同时复核 RuleDraft Schema、字段映射、参数、试运行/审批后执行一致性和重复运行语义指纹。运行轨迹符合 `schemas/rule-authoring-trace.schema.json`，只保存参数摘要和哈希，不保存原始单元格值或 API Key。

v1.0 由本地 `RuleAuthoringWorkflow` 控制 `collecting → compiling → draft → validated → dry_run_complete → awaiting_approval → approved → executed` 等状态；使用 RAG 时会显式经过 `retrieving`。工作流绑定报告哈希、输入哈希、参考日期、指标集合和请求指纹，模型不能指定状态、审批、执行或恢复点。Provider、试运行或正式执行失败后，只能针对同一请求指纹恢复到失败前状态一次；页面刷新和重复提交不会重复审批或重复正式执行。页面最多保留 20 条当前 Streamlit 会话内的脱敏工作流摘要，可查看、下载或清空；关闭会话即失效，不提供数据库、登录、跨用户共享或跨会话恢复。协议见 `schemas/rule-authoring-workflow.schema.json` 和 `schemas/rule-authoring-history.schema.json`。

v1.1 在初始页面增加“评估前 AI 规则生成”：用户可为任一已选目录指标填写补充规则，可在输入框中描述一条自定义规则，也可导入 TXT、Markdown、CSV、Excel、JSON、JSONL 或 NDJSON 规则文件。文本文件每个非空行一条；表格使用“规则描述”列和可选“指标ID”列；JSON 使用字符串数组或规则对象数组。单个规则文件上限 2 MiB、最多 100 条。系统只把规则描述和脱敏画像交给 Provider，逐条生成 RuleDraft；任一规则缺字段、阈值、允许值、频率、正则、触发值或比较关系时，页面按指标/文件行号立即列出待补信息且不会启动最终评估。全部草案通过后才合并为一个 RulePack，统一试运行、人工审批并正式评估，不执行部分成功的规则批次。

## 部署与启动

要求 Python 3.10 或更高版本。

```bash
git clone <你的私有仓库地址>
cd government-dataset-quality-demo
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run_demo.py
```

Windows PowerShell 请将激活命令替换为：

```powershell
.venv\Scripts\Activate.ps1
```

启动后，在终端显示的本地地址（通常为 `http://127.0.0.1:8501`）打开页面。停止服务时按 `Ctrl+C`。

也可以直接使用 Streamlit：

```bash
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1
```

运行不依赖网络的 v0.9.1 Agent Harness：

```bash
.venv/bin/python run_agent_harness.py
.venv/bin/python run_agent_harness.py --output reports/agent-harness.json
```

默认仅对本地模板 Provider 做金标回放。如需对比已配置的 DeepSeek，可重复使用 `--provider template --provider deepseek`；外部模型失败会记录为 Harness 失败，不会回退成模板成绩。

命令行模式默认生成可供系统对接的严格 `report.json`；若需人可读报告，可显式指定 `.md` 输出：

```bash
.venv/bin/python -m src.cli sample_data/good_dataset.csv
.venv/bin/python -m src.cli sample_data/good_dataset.csv --output reports/report.md
.venv/bin/python -m src.cli sample_data/good_dataset.csv \
  --metric exact_duplicate_rate \
  --metric db31_030300 \
  --metric db31_030400
```

`--metric` 可重复使用；未提供时使用原 v0.4 的 13 项默认选择。可用 ID 也会显示在 `python -m src.cli --help` 中。

## Agent 与规则增强模式

报告诊断 Agent 继续只读消费结构化 `QualityReport`。它不会重新计算用户选中的指标、改变风险等级、修改阈值或接触原始字段值。页面中的“概括结果”“优先整改事项”“解释无法评估项”和报告问答都必须由用户显式触发。

“规则增强”页签提供本地引导问题和字段候选，但不会自动启用任何规则。规则草案先绑定当前报告哈希、输入哈希和评估基准日期，再由确定性校验器检查字段、类型、范围和资源边界。只有用户输入本地自声明的审批人、勾选确认并点击批准后，系统才会从当前上传字节重新执行原解析和**完全相同的指标选择**，再追加业务规则指标与风险。当前所选指标的基线报告始终保留且不被覆盖；草案、文件、工作表、数据集名称、基准日期或指标选择变化都会使原审批失效。

“补充评价标准”中的目录指标规则和自定义规则继续共用 v1.0 工作流协调层。v1.1 的评估前批次复用同一 RuleDraft、Rule DSL、RulePack 校验和确定性引擎，并采用全批次通过才可审批的语义。页面展示稳定 `workflow_id`、当前状态、状态转换、一次恢复额度、审批 ID 和执行结果 ID；历史只记录草案/试运行哈希、证据 ID、计数和状态，不记录自然语言原文、原始上传字节或 API Key。

规则草案的字段、参数校验、试运行和执行均在本地处理；配置外部模型时，评价依据和脱敏字段画像会发送给所选模型用于编译。原始单元格值不会发送。当前 Demo 没有登录或身份认证能力，审批记录中的审批人仅为本地自声明标识，不代表系统已经验证其身份。

每次规则重评最多检查 2,000,000 个规则字段值并生成 200,000 条规则问题位置；超限时整次增强评估会明确拒绝，不会静默截断位置。数值规则只接受绝对值不超过 `1e308` 的有限数字。

为了便于无 API 的本地演示，未配置 API Key 时使用本地模板，也不会把报告发送到外部服务。正式使用 Agent 或规则 Agent 时，应在启动页面侧栏展开“大模型 API 配置”，填写以下三项：

- API 地址：完整的 `/chat/completions` 地址，或服务根地址；
- API Key：该服务的访问密钥；
- 模型名称：该 API 对应的模型标识。

填写后，“只读报告诊断 Agent”和“补充评价标准 Agent”都会使用这组配置。接口需要兼容 OpenAI Chat Completions 的请求和响应格式。若仍希望使用旧的部署环境变量方式，也可以在启动前设置：

```bash
export QUALITY_AGENT_PROVIDER=deepseek
export DEEPSEEK_API_KEY="<你的 API Key>"
export DEEPSEEK_MODEL="deepseek-v4-flash"
python3 run_demo.py
```

`DEEPSEEK_MODEL` 可切换模型，`DEEPSEEK_API_URL` 可覆盖默认接口地址。本项目通过 `httpx` 直接调用 Chat Completions，不依赖 OpenAI API 或 SDK。页面自定义模型使用不依赖工具调用的普通消息模式，并会在端点不支持 JSON 模式等可选参数时自动重试兼容请求；模型可返回标准 JSON 或完整文本，系统会整理为 Agent 解读。已配置外部模型时，API 超时、鉴权失败、响应为空或规则解析失败会直接在页面显示原因，不会回退模板或继续生成假结果。API Key 不会写入报告、Agent 审计信息或缓存键。

启用外部模型前仍应完成所在单位的数据分类分级、服务采购和跨境/外发审批。白名单上下文虽然不包含原始单元格值，但字段名、聚合统计和风险说明仍可能属于内部元数据。

## 使用方式

1. 上传 CSV、`.xls`、`.xlsx`、`.json`、`.jsonl`、`.ndjson`、`.geojson` 或同构 JSON 分片 `.zip` 文件；单文件上限为 50 MiB。
2. 可选填写数据集名称；Excel 可选填写工作表名称；如需模型增强，可在侧栏“大模型 API 配置”中填写 API。
3. 选择评估基准日期和评价指标；可使用原 v0.4、仅 DB31/T、全部指标快捷预设，也可逐项自由组合。
4. 如需在最终评估前生成规则，展开“给默认指标补充评判规则”，或填写“评估前自定义规则描述”，也可导入规则文件。点击“AI 检查并生成规则”；若描述不完整，先按页面列出的字段、阈值、取值、频率或条件要求修改后重新生成。
5. 全部规则通过后，检查合并 RulePack 与确定性试运行摘要，填写审批人并确认，点击“批准规则并运行质量评估”。若没有补充或自定义规则，直接点击“运行质量评估”。报告使用本次选中的指标和已批准规则，选择顺序不影响基线指标顺序或报告哈希。
6. 查看风险提示、质量指标、数据画像与无法评估项，并按需下载结构化 JSON、Markdown 评估报告或疑似问题位置 CSV。评估前生成的业务规则结果会在报告顶部单独展示来源、审批和新增指标。
7. 在“Agent 解读”页签中按需生成报告概括、优先整改建议、无法评估项说明，或询问仅基于当前报告的问题；若填写了页面 API 配置，此处会调用对应模型。
8. 如需业务规则增强，在“规则增强”页签回答少量字段问题，生成并检查草案；明确批准后查看当前所选指标基线与增强结果的本次差异，并下载已审批 RulePack、增强结果和规则问题位置 CSV。
9. 报告生成后仍可在“补充评价标准”和“自定义规则（v1.0）”中使用原有单条可恢复工作流。点击解析查看 RuleDraft 和工作流状态，确认校验通过后试运行，最后填写审批人并明确批准。失败时页面只允许对原请求重试一次；页面底部可查看、下载或清空当前会话历史。模糊依据会进入澄清；跨表参照、任意 Python / SQL / 脚本和自动修复会被拒绝。
10. 如需使用标准依据，可在运行评估前直接打开“标准依据 RAG”页签，在页签内上传 Markdown、TXT 或 PDF 文档；确认来源后加入知识库。系统会自动识别标题、标准号和版本，按需展开元数据修改；准备好业务数据并生成报告后，回到 RAG 页签按指标、标准号、版本和来源用途筛选，确认结果没有冲突后选择可定位片段并绑定到规则编制。绑定片段会成为 `standard_clause` 或 `data_dictionary` 类型的 `RuleEvidence`。知识库只处理标准/字典/用户规范，不接收业务数据文件，文档变更或移除后需要重新检索绑定。

疑似问题位置只在独立 CSV 中提供。记录序号从 1 开始，表示解析后的记录顺序，不包含 CSV/Excel 表头；它不是物理文件行号。当前可定位字段缺失、空白记录、类型不一致、格式异常、重复记录、时间信息缺失或不可解析、来源/版本信息缺失和 IQR 统计异常。CSV 写入每项指标定位到的全部位置，不做静默截断，只包含指标名称、字段名称、问题类型、记录序号及重复记录的关联序号，不包含原始单元格值；重复记录行的“备注”会直接说明当前记录与哪条首次出现的记录完全相同或规范化后相同。位置明细不会进入页面表格、JSON、Markdown 或 Agent 上下文。

JSON 支持以下表格型形态：

- 单条扁平对象或扁平对象列表；
- 首行为表头的二维数组；
- 位于 `data`、`rows`、`records`、`items`、`list` 或 `result` 下的唯一表格；
- `.jsonl` / `.ndjson` 中每个非空行一条扁平对象；
- `.zip` 中由上述 `.json` / `.jsonl` / `.ndjson` 组成的同构分片。

对象记录示例：

```json
[
  {"名称": "事项 A", "年份": 2025, "数量": 120},
  {"名称": "事项 B", "年份": 2025, "数量": 80}
]
```

二维数组示例：

```json
[
  ["名称", "年份", "数量"],
  ["事项 A", 2025, 120],
  ["事项 B", 2025, 80]
]
```

只有可唯一判定的接口包装会自动提取，并在运行信息中留下 warning。JSON 读取支持 UTF-8、带 BOM 的 UTF-16 / UTF-32 和 GB18030；非 UTF-8 读取会显式提示。

ZIP 分片直接从压缩流读取，不按成员路径解压落地。矩阵分片必须具有完全一致且同序的表头，对象分片必须具有相同字段集合；两种结构不能混合。ZIP 会预检路径、重复成员、符号链接、加密条目、条目数、单分片与总展开体积及压缩比，且只允许 Stored / Deflated 压缩方法。任一分片失败或结构冲突时整体拒绝；包级剩余资源预算会在下一分片物化前检查。ZIP 内全部分片合计仍受 200,000 条 JSON 记录上限约束。

GeoJSON 仅支持顶层 `FeatureCollection`：一个 `Feature` 固定对应一条记录；每个 Feature 必须显式包含 `properties` 和 `geometry`，可选 `id` 只能是字符串或有限数值。白名单仅包括扁平 `properties`、`Feature.id` 和 `geometry` 的类型、坐标位置数、坐标维度及二维范围摘要。原始 `coordinates` 永不展开或导出；嵌套 `properties`、白名单外嵌套路径、未支持几何类型、非法线/多边形基数、未闭合线性环和非有限坐标会明确失败。GeoJSON 不可作为 ZIP 分片使用。

当前仍不支持普通嵌套对象/数组的自动展平、非 FeatureCollection 的 GeoJSON、注释、尾逗号或其他 JSON5 容错。仅针对已确认的 `{[...]}` 整体外壳做定向修复，且必定记录 warning。

## 功能边界

- 内置确定性数据画像、43 项可选指标目录与风险规则，无需模型 API；
- 原 v0.4 的 13 项指标与 DB31/T 的 30 项指标使用不同稳定 ID；重复语义不会被去重，报告记录目录版本和规范化后的选择集合；
- DB31/T 的 28 项外部依据型指标在当前单表输入下明确标记为无法评估；原有指标只作为可用代理线索展示，不被冒充为标准得分；
- `QualityReport` 是指标和风险的唯一事实源；Agent 输出使用独立 `AgentAnalysis`，不会回写报告；
- `RulePack`、审批记录和规则增强结果使用独立协议；未批准、非法、审批后被修改或与当前输入不匹配的规则不会进入引擎；
- 规则增强只追加确定性业务规则结果，不修改当前所选基线指标、既有风险或默认阈值，也不实现 v0.5 的跨历史版本“改善/恶化”判断；
- 人工确认绑定当前草案哈希；重新生成或修改草案后必须重新勾选确认，后端执行分支也会再次校验；
- 每条 Agent 事实和整改建议都引用当前报告中的 `metric_key`、`risk_id`、无法评估项或报告摘要；
